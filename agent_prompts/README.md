# Промпты следующей волны

Каждый файл самодостаточен и уже содержит общую часть: состояние проекта, LM Studio, требования к безопасности, воспроизводимости, бюджетам и логам.

Порядок запуска:

1. `E_python_signal_collector.md` и `F_sql_signal_collector.md` — разработка может идти параллельно в отдельных worktree, реальные вызовы одного LM Studio выполнять по очереди.
2. `G_signal_analysis.md` — после завершения E и F.
3. `H_low_data_policy_selection.md` — только если G разрешает динамический выбор.
4. `I_automatic_harness_generation.md` — адаптеры можно готовить параллельно, оптимизацию запускать после фиксации данных и бюджетов.
5. `J_independent_audit.md` — последним, после заморозки результатов.

Альтернативный рекомендуемый путь после H:

- `K_master_harness_optimization_experiment.md` — один агент выполняет актуальный поиск методов, исправляет методические проблемы H, реализует автоматическую генерацию harness, проводит малоресурсный эксперимент через LM Studio и самостоятельно пересчитывает результаты. При использовании K отдельно запускать I и J не нужно.

После разведочного результата K:

- `L_final_original_hypothesis_experiment.md` — конечная проверка исходной гипотезы: обязательное воспроизведение конкретного открытого AutoHarness/AutoSaddler-подобного framework, замена только его optimizer на настоящий RL и точно определённый TailRL либо честно обозначенный tail-aware RL, затем сравнение при слабой frozen-модели, малом числе наблюдений и коротком контексте.

Файлы предназначены для передачи агентам целиком без добавления общего блока вручную.
