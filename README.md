# Improved AutoSaddler V2 на SWE-bench Pro

## Задача

Проверяем, помогает ли улучшенная рефлексия вместе с ориентацией оптимизатора на исходный код инструментов создавать более сильный агентный харнесс. За основу взят [AutoSaddler V2](https://github.com/microsoft/AutoSaddler): его цикл поиска кандидатов, оценка и EvoDAG сохранены. Целевой агент — OpenCode 1.19.5 с Qwen3.7 Plus; оптимизатор — GLM-5.3. Бенчмарк — SWE-bench Pro V1, фиксированное деление **24 train / 16 validation / 40 test** и по **6 итераций** оптимизации H1 и H2.

Сравниваются три харнесса:

- **H0:** исходный OpenCode без оптимизации.
- **H1:** OpenCode после исходного AutoSaddler V2.
- **H2:** OpenCode после AutoSaddler V2 с добавленной адаптивной памятью рефлексии и инструкциями по обоснованным изменениям исходного кода инструментов.

## Что добавлено в AutoSaddler

У исходного AutoSaddler уже есть история кандидатов, обычные уроки рефлексии и их повторная подача оптимизатору. [AIDE ML](https://github.com/WecoAI/aideml) также использует журнал решений и его сводку как память. Наша модификация развивает эти идеи внутри AutoSaddler V2:

1. **Experiment Journal:** после каждой итерации отдельно сохраняются проблема, гипотеза, изменённые компоненты, оценки до и после патча, выигранные и проигранные задачи, следующий шаг и ссылки на исходные события.
2. **Adaptive Memory Retrieval:** для поиска кандидата, диагностики, патча и рефлексии выбираются релевантные записи журнала с проверяемыми ссылками на подробности. Оптимизатор получает их в следующей итерации.
3. **Causal Reflection:** оптимизатор обязан различать подтверждённые, опровергнутые и неопределённые гипотезы. Изменение балла само по себе не считается доказательством действия патча; ссылки на задачи ограничены train.
4. **Tool-Oriented Optimization:** инструкции направляют диагностику на реальный путь исполнения OpenCode и разрешают менять исходный код инструментов и цикла агента при наличии свидетельств и проверки сборки.

Реализация: [патч AutoSaddler](swe/improved_v2/autosaddler-v2-extension.patch), [промпты оптимизатора](swe/experiments/autosaddler_reproduction/opencode_prompt_pack.py), [конфигурация H1](swe/improved_v2/H1.yaml), [конфигурация H2](swe/improved_v2/H2.yaml). Патч применяется к AutoSaddler `e841543ce6cf6bdf690e65134b12a829ec9f66d1`.

Для подготовки исходников AutoSaddler клонируйте указанный коммит в `third_party/AutoSaddler` и выполните `git -C third_party/AutoSaddler apply ../../swe/improved_v2/autosaddler-v2-extension.patch`. Пути `storage.run_root` в YAML указывают на машину исходного прогона; для нового запуска задайте свой каталог результатов.

## Как прошла оптимизация

Оба оптимизатора завершили шесть итераций. H1 предложил шесть кандидатов, три прошли train-критерий; лучший по validation получил **5/16**. H2 предложил шесть кандидатов, два прошли train-критерий. Кандидат H2 `fa214efe…` получил **4/16** на validation. Его патч сохраняет сообщение о продолжении в БД OpenCode, когда агент останавливается после использования инструментов без правки файлов, и добавляет предупреждение при изменении тестовых файлов. Другой принятый кандидат H2 добавил блокировку правок существующих тестовых артефактов, но **не входит** в тестируемый здесь `fa214efe…`.

Новый механизм работал в реальном цикле: у H1 зафиксировано **6 обычных записей уроков**; у H2 — **6 обычных уроков, 6 новых записей журнала и 6 причинных оценок**. Трассы показывают чтение новой памяти и её использование: после неудачи первого патча оптимизатор нашёл, что сообщение о продолжении не сохранялось в БД, и исправил этот путь в следующем кандидате. В итоговых тестовых трассах предупреждение о правке тестов появилось в **27/40** задачах, а сообщение о продолжении — в **2/40**. Срабатывание механизмов подтверждено; их отдельный вклад в балл не измерялся.

## Результаты на test

| Бенчмарк | H0: исходный харнесс | H1: AutoSaddler V2 | H2: AutoSaddler V2 с новым механизмом |
| --- | ---: | ---: | ---: |
| SWE-bench Pro V1, 40 задач | **16/40 (40,0%)** | **15/40 (37,5%)** | **19/40 (47,5%)** |

H2 в таблице — конкретный кандидат `fa214efe…`, оценённый в отдельном тестовом запуске; его результат исследовательский. [План и идентификаторы кандидатов](results/improved_autosaddler_v2/plan.json) сохранены вместе с результатами. Парно с H0 он решил дополнительно 6 задач и потерял 3: разница **+7,5 процентного пункта**. Точный критерий Мак-Немара даёт **p=0,5078**; при одном запуске оптимизации статистически убедительного превосходства нет.
