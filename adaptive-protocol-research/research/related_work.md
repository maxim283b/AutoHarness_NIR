# Аналоги (проверено 8 октября 2026 года)

Проверка ограничена первичными источниками: статьями и официальными репозиториями. «Код открыт» означает, что репозиторий и исходные файлы видны; это **не** означает, что установка и результаты воспроизведены. Команды установки проанализированы, но зависимости семи систем здесь не устанавливались: многие требуют API, vLLM/модель 27B, датасеты и отдельное окружение. Поэтому фактическая работоспособность установки остаётся непроверенной.

| Работа | Что выбирается / когда | Механизм и опыт | Открытый код и пригодность |
|---|---|---|---|
| [MaAS](https://proceedings.mlr.press/v267/zhang25bi.html) | Подсеть из «агентного суперсета» под запрос до его исполнения; ресурсное распределение зависит от сложности запроса. | Обучаемое распределение архитектур, обновляемое по обратной связи предыдущих выполнений. Не простой bandit. | [Репозиторий](https://github.com/bingreeky/MaAS) есть, содержит `maas/`, `setup.py`, `requirements.txt`, команды оптимизации. Для запуска нужны внешние GSM8K/HumanEval/MATH, конфигурация MetaGPT и API. Код пригоден для идей о маршрутизации, но тяжёл для малого пилота; команда установки не выполнена. |
| [DyFlow](https://arxiv.org/abs/2509.26062) | Подцели и операторы перестраиваются **во время** решения по промежуточной обратной связи. | Designer–Executor с моделью DyPlanner; опыт предыдущих задач используется при обучении планировщика, не как простой онлайн-bandit. | [Репозиторий](https://github.com/wyf23187/DyFlow) есть, `pip install -r requirements.txt` указан; реальный запуск требует DyPlanner через vLLM и API. Идея повторного планирования полезна, готовый стек несоразмерен пилоту. Установка не выполнена. |
| [DyLAN](https://arxiv.org/abs/2310.02170) | Состав команды и взаимодействие по запросу; во время работы есть отбор агентов по раундам и ранняя остановка. | Эвристика/метрика Agent Importance Score для оптимизации команды; не обучение бандита для четырёх протоколов. Накопленный опыт используется при подборе команды. | [Репозиторий](https://github.com/SALT-NLP/DyLAN) есть, с `code/`, `exp/`, `pip install -r requirements.txt` из `code`. Демо требует ручной правки `QUERY`, API и датасеты. Можно использовать как референс многократных раундов; установка не выполнена. |
| [JIT-Agent](https://arxiv.org/abs/2608.25593) | Генерирует/чинит конфигурацию harness под задачу перед исполнением и по полученным traces; выбирает память, планирование, действие и инструменты. | Специальный meta-LLM, архив прошлых harness и сигналов; не LinUCB. | [Репозиторий](https://github.com/bingreeky/JIT) есть, с `jit/`, `harness_factory/`, `benchmark/`; инструкция `conda env create -f environment.yml` или `pip install -r requirements.txt`. Требует нескольких модельных ролей/API, а для полного метода — meta-model. Для эксперимента можно позаимствовать модульность, не генерацию кода harness. Установка не выполнена. |
| [AutoSaddler](https://arxiv.org/abs/2608.23041) | Офлайн улучшает prompts, инструменты, middleware и цикл harness между партиями задач, а не переключает готовые протоколы внутри одной задачи. | Диагностика traces, структурные патчи и отбор по validation; накапливает опыт. | [Репозиторий Microsoft](https://github.com/microsoft/AutoSaddler) есть. V2 имеет детерминированный smoke; инструкция требует Python 3.12–3.14 и `uv sync --extra dev`, тогда как опубликованные эксперименты относятся к V1. Для малого пилота полезны event log и provenance. Установка не выполнена. |
| [Symphony-Coord](https://arxiv.org/abs/2602.00966) | Маршрутизирует подзадачи к агентам **во время** работы; двухэтапный beacon screening + LinUCB. | Контекстный бандит с отложенной наградой и памятью предыдущих взаимодействий. | В [странице статьи](https://www.alphaxiv.org/abs/2602.00966) ссылка на официальный код не обнаружена; поиск по точному названию также не дал достоверного авторского репозитория. Похожие проекты Symphony не приравнивались к реализации статьи. Переиспользование кода пока не подтверждено; установить нечего. |
| [TRACER](https://arxiv.org/abs/2605.28699) | На каждом раунде решает, обновлять ли предложение и говорить ли reviewer. Это управление ходами, близкое к внутритасковому переключению. | Regret matching контроллеров + role-specific GSPO/RL генерации; опыт обучения переносится между задачами. | [Репозиторий](https://github.com/Shark-Forest/TRACER) есть, `requirements.txt`, `run_experiment.py` и mock-smoke команда. Для реального режима нужны веса, ресурсы и датасеты. Идея turn-level контроля релевантна; полноценный RL здесь не воспроизводится. Установка не выполнена. |

## Вывод для прототипа

Идея адаптации уже исследуется: MaAS делает условный выбор архитектуры под запрос, DyFlow перестраивает workflow во время работы, Symphony-Coord использует LinUCB для маршрутизации, TRACER управляет ходами. Поэтому утверждать новизну общей идеи нельзя. Узкая проверяемая ниша пилота — **одни и те же четыре заранее реализованных протокола**, одно состояние задачи, одинаковая модель, фиксированный бюджет и сравнение начального выбора с реальным переключением после видимой ошибки. Переиспользование больших стеков потребовало бы больше интеграционной работы, чем сама проверка гипотезы.
